Guide T3 Code

Mode d'emploi des réglages pour travailler avec plusieurs projets, plusieurs agents en parallèle, un worktree par tâche, plusieurs machines et le téléphone. Ce qu'il faut toucher, ce qu'il vaut mieux laisser.

Rien n'a été modifié. Ce guide vient d'une lecture des onze sections de Settings, dans l'app et dans un navigateur appairé en lecture seule. En lecture seule, certaines valeurs sont masquées : un contrôle invisible ne veut pas dire « désactivé ». Ces cas sont marqués à vérifier.

L'essentiel

Six choses à retenir

  • Un serveur, plusieurs fenêtres. Les agents tournent sur une machine (le serveur). L'app, un onglet Chrome ou le téléphone ne sont que des fenêtres dessus. Il n'y a pas de commande « nouvelle fenêtre » dans l'app, mais un onglet Chrome appairé marche très bien comme deuxième fenêtre.
  • Un thread reste sur sa machine. Changer de machine, c'est déplacer le code avec Git (push, puis pull), pas le thread.
  • Settle ≠ merge ≠ suppression. Settle range un thread dans les terminés. Archive le cache. Delete le supprime. Aucun des trois ne fusionne une branche.
  • Le nettoyage des worktrees efface les fichiers ignorés. Le garde-fou protège les modifications non commitées, pas les .env. Sauvegarde-les avant d'activer le nettoyage.
  • Queue ou Steer. Un message envoyé pendant qu'un agent travaille attend son tour (Queue). ⌘+Enter fait l'inverse : il corrige l'agent en cours de route (Steer).
  • Une connexion n'est pas une synchronisation. Accéder au Mac depuis le téléphone ne copie rien entre machines.

À ne pas toucher

Ce qu'il vaut mieux laisser tel quel

  • Delete confirmation : on. C'est ta seule protection contre une suppression accidentelle.
  • Storage → Delete now : ne clique pas « pour voir ». Lis d'abord Last run, qui montre ce qui aurait été supprimé ou gardé.
  • Start from remote : on, c'est bien. Exception : pour une branche qui dépend de commits pas encore poussés, choisis la base locale au moment de créer le worktree.
  • Continue threads after restarts : on. Les threads repartent après une mise à jour ou un crash.
  • Send shortcut : Enter. Comme tu dictes, fais attention : Enter envoie tout de suite. Si ça t'arrive trop souvent, passe à ⌘+Enter.
  • Providers : Claude et Codex sont connectés. N'ajoute pas d'autres fournisseurs Git (GitLab, Bitbucket…) sans en avoir besoin, GitHub suffit.
  • Permissions des connexions : ne donne pas plus de droits à un appareil que nécessaire. Lecture seule pour consulter, accès complet seulement pour l'appareil depuis lequel tu lances des tâches.
Worktrees

Un worktree par tâche, et le ménage après

Un worktree est une copie du dépôt sur sa propre branche. Chaque tâche a la sienne, donc les agents ne se marchent pas dessus. Le cycle complet : branche → commits → push → PR → merge → nettoyage.

Le nettoyage se règle dans Settings → Storage. Valeurs observées :

RéglageÉtatEffet
Delete merged worktreesDifférent selon la machineSupprime le worktree quand la PR est fusionnée et que ses commits sont dans la branche principale.
Delete worktrees with deleted threadsDifférent selon la machineSupprime le worktree quand tu supprimes le thread.
Delete settled worktreesoffSupprime après un délai une fois le thread terminé. 0 jour = au prochain passage.
Delete inactive worktreesoffSupprime après X jours sans activité.
Delete unchanged worktreesoffSupprime ceux qui n'ont aucun commit en plus de la branche principale.
Keep worktrees with local changesUncommitted changesGarde ceux qui ont des modifications non commitées ou des fichiers non suivis. Pas les fichiers ignorés, donc pas les .env.

  1. Mets les secrets à l'abri

    Vérifie que chaque .env utilisé dans un worktree existe aussi ailleurs (dossier principal du projet, gestionnaire de mots de passe).

  2. Choisis la machine

    En haut de Storage, sélectionne une seule machine à la fois pour voir son vrai état, puisqu'elles diffèrent.

  3. Active les deux suppressions utiles

    Delete merged worktrees et Delete worktrees with deleted threads, sur chaque machine où tu codes. Laisse le garde-fou sur Uncommitted changes.

  4. Contrôle

    Après le prochain passage, lis Last run : nombre supprimé, nombre gardé, et pourquoi.

Supprimer un worktree efface ses fichiers locaux, pas la branche ni l'historique du thread.

Threads

Organiser et grouper ses threads

  • Project grouping (on) regroupe un même dépôt présent sur plusieurs machines sous un seul projet. Ça ne crée pas d'arbre de threads.
  • Fork : nouveau thread qui part d'un point de la conversation, pour tester une piste. Merge back renvoie ensuite son contexte au thread d'origine.
  • Sous-tâches : quand un agent délègue, les sous-tâches restent rattachées à son thread.
  • Pin, Snooze, Settle, Archive pour ranger. Les threads « settled » n'apparaissent pas dans Archive.
  • Settle automatique : à la fusion d'une PR (on), à sa fermeture, et après 3 jours sans activité (on). Une nouvelle activité réactive le thread.
  • Les projets sans Git ne profitent ni du regroupement par dépôt ni des worktrees. Fais un git init là où tu en veux.
Connexions

Autre fenêtre, téléphone, VPS ou Mac mini

Ouvrir T3 dans Chrome (deuxième fenêtre)

  1. Crée un lien

    Settings → Connections → Create link. Choisis les permissions, crée, copie.

  2. Colle-le dans la barre d'adresse

    Le lien complet, dans la barre d'adresse de Chrome, pas dans le champ Pairing token. Il expire au bout de cinq minutes s'il n'est pas utilisé.

  3. C'est fait une fois

    Le navigateur reste autorisé. Chaque nouvel appareil ou navigateur demande son propre lien.

Les préférences d'affichage et de notifications sont propres à chaque client : Chrome n'hérite pas de celles de l'app.

Depuis le téléphone

  • Une app existe pour iPhone/iPad et Android : liens dans Settings → About → Mobile app.
  • Sur le même Wi-Fi : Network access est déjà activé.
  • Hors de chez toi : active T3 Connect (le plus simple, avec ton compte) ou Tailscale HTTPS (réseau privé entre tes appareils). Une seule des deux suffit. Les deux sont off aujourd'hui.
  • La machine qui fait tourner les agents doit rester allumée et éveillée.

VPS ou Mac mini

  • Un environnement SSH (ton VPS) est déjà connecté dans l'app. Il n'apparaît pas automatiquement dans Chrome.
  • Choisir le VPS ou le Mac mini, c'est choisir où tournent les agents. Une machine toujours allumée te permet de lancer de longues tâches et de les suivre du téléphone.
  • Pour changer de machine en cours de travail : résumé de contexte, git push, puis sur l'autre machine git pull et nouveau thread.
  • Load balancing (off) : inutile tant que tu n'as pas plusieurs machines à répartir.

Reste à vérifier

À contrôler dans l'app quand tu ne travailles pas

  • Storage : l'état réel de chaque machine pour les deux suppressions qui diffèrent.
  • Source Control : Automatically pull, Default merge method, Worktree branch naming, writing style.
  • Integrations : Agent browser access, profils navigateur, Device hub.
  • Keybindings : la liste complète des raccourcis.
  • Providers : Health check interval, et les réglages de chaque modèle.
